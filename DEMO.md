# Демо: что показывать и как запустить

**Продукт:** пешеходный планировщик прогулок по Гродненской области. Пользователь
описывает прогулку на **русском или английском**, задаёт фильтры, получает маршрут
с объяснением. Подробная спецификация — `docs/specs/002-grodno-guide-rebuild/spec.md`;
принципы — `docs/specs/constitution.md`.

---

## Запуск стека перед демо (5–10 минут в первый раз)

```bash
cd /workspaces/demo

# 1. БД и Valhalla (тайлы строятся ~5–10 мин при первом запуске)
docker compose up -d db valhalla

# 2. Дождаться Valhalla
until curl -fsS http://localhost:8002/status >/dev/null 2>&1; do
    echo "waiting for valhalla..."; sleep 5
done

# 3. Собрать и поднять фронт
docker compose up -d --build frontend
```

Агент запускается **на хосте** (не в compose), чтобы правки кода не требовали
пересборки образа:

```bash
cd /workspaces/demo/backend
export DATABASE_URL=postgresql://grodno:grodno@localhost:5432/grodno
export VALHALLA_URL=http://localhost:8002
# OPENROUTER_API_KEY=sk-or-...   # см. ниже: без ключа агент работает в режиме fallback
.venv/bin/python -m uvicorn agent.main:app --host 0.0.0.0 --port 8080
```

Проверка одной командой, что всё живо:

```bash
curl -s -o /dev/null -w "front=%{http_code}\n" localhost/
curl -s -m 120 -X POST localhost/routes/generate \
  -H 'content-type: application/json' \
  -d '{"query":"замки Гродно","time_budget_minutes":90}' \
  -o /tmp/r.json -w "agent=%{http_code}\n" \
  && python3 -c "import json; d=json.load(open('/tmp/r.json')); print('точек', len(d['points']))"
```

Фронт открывается через порт 80 (Codespace: PORTS → 80 или
`https://<workspace-name>-80.app.github.dev`). **Перед записью — hard refresh
(Ctrl+Shift+R):** бандл пересобирается, старый кэш покажет старый вид.

## Режим без `OPENROUTER_API_KEY` (деградированный путь)

Без ключа агент переходит в **keyword-fallback**:

- embeddings не вычисляются → векторный поиск пропускается;
- intent определяется детерминированным regex/keyword-парсером вместо модели;

`/health` возвращает `"llm": false, "embedder": false`. Маршрут **всё равно строится**
— детерминировано, по явным ключевым словам и категориям. Семантически сложные
запросы («тихое место для семьи с детьми») в этом режиме могут дать менее точный
пул кандидатов.

## Сцена 1 — старт (15 секунд)

Слева панель «AI-гид по Гродно»: сегмент-контрол **Планирование | Проводник**,
чипы быстрых запросов (замки, костёлы, монастыри, где поесть), выбор времени
(30 мин / 1 ч / 2 ч / полдня / **без ограничения**), транспорт (пешком, велосипед,
машина, как удобно). Карта — реальные OSM-данные Гродно.

Слова: «Это планировщик прогулок по Гродненской области: описываете, что хотите
увидеть на русском или английском — агент собирает маршрут по реальным тропинкам
через Valhalla, а места ищет гибридным поиском по точкам Гродненской области».

---

## Сцена 2 — основной маршрут (30–60 секунд, ждём ~20 с при живом LLM)

Запрос: **«Хочу посмотреть замки и костёлы Гродно»**, транспорт **пешком**, время
**без ограничения**.

Показать на карте: линию маршрута, нумерованные точки, в панели — список остановок
с категориями. Ключевая фраза: «Если время не указано, мы его не выдумываем —
маршрут строится целиком».

---

## Сцена 3 — уточнение (30 секунд)

В том же поле: **«добавь по пути кофейню и туалет»** (или: **"add a café and toilet
along the way"** — EN-запрос работает так же).

Ожидаемо: число остановок вырастает, все прежние сохраняются, новые точки лежат
в нескольких сотнях метров от маршрута (кафе и туалеты ищутся по близости к
существующим остановкам, не по глобальной релевантности).

Фраза: «Прежние остановки не теряются, а новые берутся не по релевантности,
а рядом с маршрутом — чтобы не получилось кафе за 12 километров».

---

## Сцена 3а — каталог вместо маршрута (30 секунд)

Переключатель «что показать» → **каталог**. Запрос: **«все костёлы Гродненской области»**.
Ожидаемо: вместо одной прогулки приходит **список** мест, сгруппированный по городам, без
линии на карте; в ответе нет ни геометрии, ни бюджета — это честно, потому что маршрута ещё
нет. Затем отметить несколько точек и построить по ним маршрут.

Фраза: «Если Вы хотите не прогулку, а выбор — каталог отдаёт все находки по городам; кампанию
Вы собираете сами, и мы считаем маршрут уже по вашему выбору».

Тут же — тумблер **«круговой маршрут»**: линия возвращается в точку старта, и обратная дорога
посчитана в бюджете (замкнутый круг не выглядит дешевле, чем есть).

---

## Сцена 4 — Проводник (45 секунд, самое наглядное)

Переключить сегмент на **Проводник**. Ожидаемо: «пройдено 0 из N», карточка
**следующей остановки** крупно (номер, категория, расстояние), кнопка
**«открыть в картах»**. Нажать «пройдена» вручную на первой остановке →
счётчик растёт, следующая подтягивается.

Фраза: «Ведём туриста по маршруту: отмечаем пройденное, прогресс сохраняется,
есть ссылка в карты». На телефоне вместо панели выезжает bottom sheet.

## Сцена 5 — если спросят про качество (не показывать, а сказать)

- Голден-сет: **13 кейсов** в `backend/benchmarks/golden/*.json` (условия запроса: категории,
  запреты, регион, бюджет, паритет RU/EN) и **23 эталонные прогулки** в
  `backend/benchmarks/routes/*.json` (геометрия: recall, порядок, крюк).
- Прогон: `cd backend && .venv/bin/python scripts/bench_routes.py --base-url http://localhost:8080`
  — печатает таблицу и пишет `backend/benchmarks/report.json` / `report.md`.
- Голден-слой: `.venv/bin/python scripts/bench_routes.py --golden --snapshot "" --report-dir benchmarks`
  → `backend/benchmarks/compliance.json`.
- Одна страница по трём слоям: `.venv/bin/python reports/quality.py` — печатает свежесть
  каждого числа и **«НЕ ИЗМЕРЯЛОСЬ»**, если слоя нет; пустую страницу за хорошую не выдаёт
  (возвращает ненулевой код).
- Тесты: `cd backend && .venv/bin/python -m pytest -q`.
- Гейты (и они же в CI): `ruff check .`, `pyright`, `pytest -q`.

Честные оговорки, если спросят про цифры: сохранённый замер от 27.09 давал соответствие 67%
(8/13), и три падения — про «туалет обязателен»: туалет не попадал в **остановки**. Это не
обязательно дефект маршрута: по продуктовому решению туалет — услуга *по пути*, а не
остановка, и кейс проверял только категории остановок. Прежде чем называть число, прогоните
замер заново.

## Чего НЕ показывать

- Пустой прогон «с нуля» (freebuff) — внутренняя проверка, не для демо.
- `route-planner.tsx` — мёртвый файл апстрима, в UI не участвует.

---

## Если что-то отвалилось в кадре

| Симптом | Что делать |
|---|---|
| Панель не появилась / старый вид | hard refresh (Ctrl+Shift+R) |
| «Unknown: Could not find candidate edge…» | пересобран фронт с откатом по перегонам; построить маршрут заново |
| Ошибка сети / пустой ответ | `docker compose ps`; агент на 8080 жив? `curl -s localhost:8080/health` |
| Маршрут строится дольше 40 секунд | так и есть при живом LLM; не комментировать паузу, показать прогресс |
| `/health` → `"llm": false` | `OPENROUTER_API_KEY` не задан; агент работает в keyword-fallback |

---

## Что система не обещает

- **Часы работы** — OSM-строки `opening_hours` не проверяются на актуальность.
- **Цены и тарифы** — OSM-теги `charge`/`fee` хранятся как есть, без проверки.
- **Безбарьерный доступ** — пешеходный профиль Valhalla не учитывает пандусы и лифты.
- **Расписание автобусов и покупка билетов** — транзитные данные не загружены,
  кнопки покупки нет.

Подробнее — `docs/specs/constitution.md` §7 и `README.md` §11.
