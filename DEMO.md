# Демо: что показывать и с какими цифрами

## Перед записью (2 минуты)

```bash
cd /workspaces/demo
docker compose ps                 # db, valhalla, frontend — Up
curl -s localhost/health          # агент: db/valhalla true, llm true
```
Агент — хостовым процессом (не в compose):
```bash
cd /workspaces/demo/backend && set -a && . ~/.hermes/cache/scratch/.env_agent && set +a \
  && .venv/bin/python -m uvicorn agent.main:app --host 0.0.0.0 --port 8080
```
Фронт открывается через Codespace: порт **80** → `https://animated-space-disco-rxvrxggp666hp95q-80.app.github.dev`
(или PORTS → 80). **Перед записью — hard refresh (Ctrl+Shift+R)**: бандл пересобирается, старый кэш покажет старый вид.

Проверка одной командой, что всё живо:
```bash
curl -s -o /dev/null -w "front=%{http_code}\n" localhost/
curl -s -m 120 -X POST localhost/routes/generate -H 'content-type: application/json' \
  -d '{"query":"замки Гродно","time_budget_minutes":90}' \
  -o /tmp/r.json -w "agent=%{http_code}\n" && python3 -c "import json;d=json.load(open('/tmp/r.json'));print('точек',len(d['points']))"
```

## Сцена 1 — старт (15 секунд)

Слева панель «AI-гид по Гродно»: сегмент-контрол **Планирование | Проводник**, чипы быстрых запросов
(замки, костёлы, монастыри, где поесть), выбор времени (30 мин / 1 ч / 2 ч / полдня / **без ограничения**),
транспорт (пешком, велосипед, машина, как удобно). Карта — реальные OSM-данные Гродно.

Слова: «Это планировщик прогулок по Гродно: пишете, что хотите увидеть, он собирает маршрут по реальным
тропинкам через Valhalla, а места ищет гибридным поиском по 5965 точкам области».

## Сцена 2 — основной маршрут (30–60 секунд, ждём ~20 с)

Запрос: **«Хочу посмотреть замки и костёлы Гродно»**, транспорт **пешком**, время **без ограничения**.
Ожидаемо (замерено): **11 точек, 25 км, 298 мин в пути, «без лимита»**.
Ключевая фраза: «Если время не указано, мы его не выдумываем — маршрут строится целиком».

Показать на карте: линию маршрута, нумерованные точки, в панели — список остановок с категориями
(Земляной форт №VI, Коложская церковь, монастырь бернардинцев, Старый замок, Фарный костёл,
бригитки, Гродненская крепость, Форт 1…).

## Сцена 3 — уточнение голосом туриста (30 секунд)

В том же поле: **«добавь по пути кофейню и туалет»** (или «давай зайдём куда-нибудь пообедать»).
Ожидаемо: остановок станет заметно больше, все прежние сохраняются, новые точки ложатся в десятки-сотни
метров от маршрута (замер на сценарии «монастыри Гродно» → +кофейня/туалет: **6 → 14 остановок**,
6/6 прежних на месте, добавки в **28–258 м**; на сценарии «монастыри и храмы»: 7 → 15, 7/7, 28–247 м).
Фраза: «Прежние остановки не теряются, а новые берутся не по релевантности, а рядом с маршрутом —
чтобы не получилось кафе за 12 километров».

## Сцена 4 — проводник (45 секунд, самое наглядное)

Переключить сегмент на **Проводник**. Ожидаемо: сколько же остановок, «пройдено 0 из N», карточка
**следующей остановки** крупно (номер, категория, расстояние), кнопка **«открыть в картах»**.
Нажать «пройдена» вручную на первой остановке → счётчик растёт, следующая подтягивается.
Фраза: «Ведём туриста по маршруту: отмечаем пройденное, прогресс сохраняется, есть ссылка в карты».
На телефоне вместо панели выезжает bottom sheet — если запись с телефона, показать это.

## Сцена 5 — если спросят про качество (не показывать, а сказать)

- Голден-сет: **23 кейса** (7 прогулок по Гродно, 6 малых городов, 2 без бюджета, 2 уточнения,
  3 адверсариальных), **94 остановки**, у каждой провенанс (Википедия + OSM, лицензии CC BY-SA/ODbL),
  координаты сверены с БД. Тест схемы — 44 проверки.
- Бенчмарк: **replay байт-в-байт детерминирован** (LLM и Valhalla — версионированный артефакт),
  разделены «подбор» и «сборка»: **S1 0.33–0.62** против **S2|S1 = 1.00** — то есть собираем из найденного
  идеально, а теряем на первом этапе (в пул не попадает до 67% обязательных мест). Именно туда теперь
  и пойдут улучшения: лемматизация, категория и расстояние в реранкер.
- Тесты: бэкенд **280**, фронт — спеки панели/проводника/карты зелёные, типы чистые.

## Чего НЕ показывать

- Режим без `OPENROUTER_API_KEY` (он работает, но без ключа выдаёт ерунду — как раз чиним).
- Сухой прогон «с нуля» (freebuff) — это внутренняя проверка, не для демо.
- `route-planner.tsx` — мёртвый файл апстрима, в UI не участвует.

## Если что-то отвалилось в кадре

| Симптом | Что делать |
|---|---|
| Панель не появилась / старый вид | hard refresh (Ctrl+Shift+R) |
| «Unknown: Could not find candidate edge…» | пересобран фронт с откатом по перегонам; если всё же появилось — построить маршрут заново |
| Ошибка сети | `docker compose ps`, агент на 8080 жив? `curl -s localhost/health` |
| Маршрут строится дольше 40 секунд | так и есть при живом LLM; не комментировать паузу, показать прогресс |
