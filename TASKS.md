## Убрать Langfuse и самодельную телеметрию → Logfire

**Решение (2026-10-11):** Langfuse выпиливается вместе со всей ручной обвязкой
трассировки; наблюдение ставится на **Logfire** — родной для PydanticAI.

**Зачем:** на трейсы навалено 391 строка в `telemetry/` и 93 вызова `trace.`
по коду. PydanticAI инструментируется Logfire'ом из коробки, так что большая
часть этой обвязки не нужна.

**Область:**

| Что | Где |
|---|---|
| `telemetry/trace.py` (275) · `telemetry/progress.py` (115) | удаляются целиком |
| `core/config.py:14-16,40-44` — `LANGFUSE_*`, `langfuse_configured()` | удаляются |
| `pyproject.toml:17` — `langfuse>=3.0` | удаляется из зависимостей |
| `agent/telemetry.py` — докстринг про «Langfuse's own key names» | переписывается под Logfire |
| 93 вызова `trace.` + 13 вызовов `progress.` | удаляются вместе с модулями-носителями |
| `README.md` — упоминание Langfuse | убрать |

Logfire подключается один раз: `logfire.configure()` при старте приложения и
`logfire.instrument_pydantic_ai()` — этого достаточно, чтобы видеть и вызовы
модели, и вызовы тулзов агентского цикла.

**Проводное следствие, которое надо решить явно:** `GET /routes/trace/{id}` и
`GET /routes/progress/{id}` живут в `telemetry/` и умрут вместе с ним. Фронтенд
их **не** использует (проверено: в `frontend/src` нет ни `progress_id`, ни
`/progress`, ни `routes/trace`). Решить: удалить из API и README или оставить
как тонкие обёртки над Logfire.

**Когда делать:** фаза 5 основного рефакторинга. 93 вызова `trace.` сидят в
`planner/`, который этой фазой удаляется целиком; чистить их отдельно — значит
выбросить работу при слиянии. Порядок: `planner/` умирает → `telemetry/`
удаляется → Logfire встаёт в агентский путь один раз.

**Готово, когда:** `langfuse` нет ни в зависимостях, ни в коде; `telemetry/`
удалён; прогон запроса виден в Logfire (и вызовы модели, и вызовы тулзов);
`ruff`, `pyright` и импорт-смоук чисты.
