# План развития маршрутного ассистента Гродно

## Текущее состояние

**Что работает:** поиск достопримечательностей по ключевым словам, построение пешеходного маршрута через Valhalla.

**Проблемы:**
- Категории определяются LLM (Qwen 1.5B) — модель путает категории («горисполком» → «инфраструктура» вместо «архитектура»)
- Жёсткий фильтр по категории в SQL отсекает релевантные места
- Пользователь задаёт количество точек — это неестественно (никто не планирует «4 точки»)

---

## Цель

**Conversational AI-гид по Гродно** — система, которая:

1. Понимает свободный текст (не ключевые слова)
2. Учитывает интересы, время, погоду, логистику
3. Объясняет, почему выбрала места
4. Адаптируется к контексту разговора

Пример:
> «Хочу прогуляться, интересны музеи»
> → LLM определяет intent: discovery + museums
> → «В Гродно 5 музеев. Ближайшие — Галерея Арсенал (искусство, открыта до 18:00) и Аптека-музей (история, 15 BYN). Прогулка по трём — ~3 часа. Погода 22°C, влажность 75%, возможен дождь к вечеру. Возьмите воду и удобную обувь.»

---

## Архитектура: два режима

### Режим A — Fast path (стабильный, сегодня)
Для простых запросов: категория определяется по ключевым словам в тексте.
- Если пользователь написал «замки» → фильтр по категории «замок» (точно)
- Если написал «музеи» → фильтр по «музей»
- LLM не вызывается → нет галлюцинаций, нет задержки 2-3 секунды
- **Результат:** 200-400ms, предсказуемо

### Режим B — Conversational reasoner (следующий этап)
Для сложных запросов: LLM выступает центральным reasoner.
- Анализирует контекст: интересы, время, погода, часы работы
- Выбирает места по смыслу, не по ключевым словам
- Генерирует объяснение: почему эти места, что нужно знать

```
Пользователь → LLM Reasoner → Планирование: что, в каком порядке, с какой информацией
                    ↓
              Инструменты:
              - Семантический поиск мест
              - Погода (Open-Meteo API)
              - Часы работы / билеты (если есть)
              - Маршрут (Valhalla)
                    ↓
              Ответ: связный текст + маршрут на карте
```

## Roadmap

### Этап 1: Стабильный флоу (прототип, сегодня)
**Цель:** базовый поиск работает без галлюцинаций, быстро

- [ ] Доверительный поиск: категория из ключевых слов → софт-фильтр, не WHERE
- [ ] Бюджет времени вместо количества точек (пользователь пишет «3 часа», не «4 точки»)
- [ ] Фиксированный seed: тот же запрос → тот же маршрут (детерминизм)

### Этап 2: Context-aware (1-2 недели)
**Цель:** система учитывает контекст, не только текст

- [ ] conversation_id: запоминание контекста между запросами
- [ ] user_interests: «интересует история» → приоритет музеев и замков
- [ ] preferences: «с детьми» → парки, музеи вместо кладбищ

### Этап 3: Conversational guide (2-4 недели)
**Цель:** полноценный AI-гид, не поисковик

- [ ] LLM-as-reasoner: центральный LLM вызывает инструменты, рассуждает
- [ ] Интеграция погоды: Open-Meteo (бесплатный API, без ключа)
- [ ] Дополнительная информация: часы работы, цены, что взять с собой
- [ ] Генерация объяснений: почему эти места, что особенного

### Этап 4: Production (по необходимости)
- [ ] Добавление новых мест (сейчас 76, ручная разметка)
- [ ] Другие города Беларуси
- [ ] Push-уведомления: «Вы рядом с музеем, хотите зайти?»

## Технологии

| Компонент | Технология | Почему |
|---|---|---|
| Поиск мест | pgvector (PostgreSQL) | Семантический поиск по 384-d эмбеддингам |
| Эмбеддинги | paraphrase-multilingual-MiniLM-L12-v2 | 384-d, работает с русским, быстро на CPU |
| LLM парсер | Qwen2.5-1.5B-Instruct (GGUF) | Локально, без API-ключей, ~2s на запрос |
| LLM reasoner | Qwen2.5-7B-Instruct илиMistral-7B | Больше контекста, лучше рассуждения |
| Маршрут | Valhalla | Open-source routing engine, пешеходный режим |
| Погода | Open-Meteo API | Бесплатно, без ключа, hourly forecast |
| UI | React + Valhalla web-app | Карта + маршрут |

## Метрики успеха

| Метрика | Целевое значение |
|---|---|
| Время ответа (fast path) | < 500ms |
| Время ответа (conversational) | < 5s |
| Точность категорий | > 90% (сегодня ~60% из-за LLM) |
| Пользователь satisfaction | > 4/5 |
| Покрытие кейсов (бенчмарк) | > 80% |

## Риски и mitigations

| Риск | Mitigation |
|---|---|
| Qwen 1.5B путает категории | Fast path: ключевые слова, LLM только как fallback |
| LLM-ответы не соответствуют реальности | RAG: LLM видит только данные из БД, не галлюцинирует |
| Погода неточная | Подтягивать с ±2h окном, предупреждать о неопределённости |
| Медленный LLM (7B) | Кэш, async generation, streaming |
