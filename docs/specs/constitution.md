# Constitution — Grodno Travel Agent

Принципы, обязательные для любого изменения в этом репозитории (SDD: спека → план → задачи → реализация).

1. **Спека раньше кода.** Любое функциональное изменение начинается с `specs/<capability>/spec.md` (требования, критерии приёмки), затем `plan.md` (технический план) и `tasks.md` (чек-лист). Код пишется только под существующую спеку.
2. **Одна способность — одна папка.** `specs/NNN-slug/` содержит spec/plan/tasks одной способности. Нумерация сквозная, файлы не переименовываются после создания.
3. **Данные — код.** Датасеты живут в `data/` в текстовых CSV, версионируются в git, применяются идемпотентными скриптами из `scripts/`. Никаких «знаний», зашитых только в БД.
4. **Идемпотентность.** Любой скрипт можно запускать повторно: upsert по естественному ключу (`source_url`), миграции `ADD COLUMN IF NOT EXISTS`, seed не ломает существующие строки.
5. **Graceful degradation.** Отсутствие внешних ключей (OpenRouter) или сервисов (Valhalla) не должно ронять API: деградация до keyword-поиска / пустого shape с честным статусом в `/health`.
6. **Координаты — WGS84, порядок lon/lat только внутри PostGIS/Valhalla.** В датасетах и API — lat/lon.
7. **Данные о часах работы и ценах — справочные.** В датасете они помечены как ориентировочные (`README`), обязательное поле `source_url` ведёт к источнику для проверки.
8. **Проверяемость.** Изменения агента покрыты smoke-тестами (`scripts/smoke_test.sh` или pytest), schema-изменения — миграцией в `db/migrations/`, применимой к живой БД.
9. **Чистый английский в коде и коммитах**; пользовательские тексты (blurb/fun_fact) — на русском.
