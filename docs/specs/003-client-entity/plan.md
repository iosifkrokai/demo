Способность описана в `spec.md` (ТЗ 003). Здесь — исполнимый план: что уже сделано, границы работ,
замороженные интерфейсы и порядок проверки. Чек-лист — `tasks.md`.

Файл появился позже самой реализации: по конституции §1 план и задачи обязаны идти до кода, и этот

## 0. Состояние на входе (измерено на этом дереве)

- **Бэкенд готов и покрыт тестами:** `clients_api.py` (8 маршрутов под `/clients/me`),
  `clients_store.py` (`PostgresClientRepository`, `ClientRepository`), `clients_models.py`.
  `pytest tests/test_clients.py` → **53 passed**. В OpenAPI все `/clients/me*` пути присутствуют.
- **Схема:** миграция `db/migrations/0005_clients.sql` (`clients`, `client_preferences`,
  `saved_routes` + индекс), та же DDL влита в `db/init.sql` (иначе свежий том приезжал без этих
  таблиц). Идемпотентность проверена применением файла к живой БД с уже созданными таблицами —
  без ошибок и без потери строк.
- **Фронтендовая фича написана, но недостижима из entry:** `api/client.ts`,
  `hooks/use-client-routes.ts`, `hooks/use-client-preferences.ts`, `components/history/*`,
  `utils/client-id.ts`. `App` рендерит только `MapComponent` + `Sidebar`, поэтому ни сохранение
  маршрута, ни предпочтения сейчас не вызываются и `X-Client-Id` на `/clients/*` не уходит.
- **Инфраструктура:** nginx проксирует `/clients/` и разрешает `X-Client-Id` в предполёте;
  у агента `X-Client-Id` добавлен в `allow_headers` CORS (раньше предполётный запрос браузера
  отбрасывался).

## 1. Целевой поток

```
браузер: localStorage.grodno-client-id (UUIDv4, создаётся один раз)
   │
   ├─ каждый запрос к агенту: X-Client-Id: <uuid>          (сервер заводит строку clients)
   │
   ├─ «сохранить маршрут» → POST /clients/me/routes {query, plan, visit_overrides}
   │     недоступно хранилище → 503 storage_unavailable → локальная копия остаётся резервом
   │
   ├─ история → GET /clients/me/routes → открыть → GET /clients/me/routes/{id} → план как был
   │
   ├─ предпочтения → GET/PUT /clients/me/preferences (предзаполняют UI, сохраняются с задержкой)
   │
   └─ «удалить мои данные» → DELETE /clients/me (cascade: маршруты + предпочтения)
```

Правило, которое не меняется: маршрут **не** сохраняется молча. Сохранение — действие туриста,
иначе список превращается в свалку. Прогресс прохода (`visited`, метры) на сервер не уезжает:
это состояние текущей прогулки, а не факт о туристе.

## 2. Замороженные интерфейсы

Изменять только вместе с этим файлом и `spec.md`.

- Схема: `0005_clients.sql` (и её копия в `init.sql`) — менять нельзя без новой миграции.
- Эндпоинты и коды причин: `/clients/me/{preferences,routes,routes/{id}}` и `DELETE /clients/me`;
  коды `storage_unavailable`, `route_not_found`, `invalid_client_id`, `too_many_routes`.
- Потолок `MAX_SAVED_ROUTES = 200` — при превышении `POST` отвечает `too_many_routes`.
- `ClientRepository` (Protocol) — граница, по которой тесты подставляют фейк вместо Postgres.
- `X-Client-Id` — UUIDv4; незнакомый/отсутствующий заголовок не ошибка, а работа без сохранения.

## 4. Как проверяется

- Бэкенд: `cd backend && ./.venv/bin/python -m pytest -q tests/test_clients.py` (+ полный набор).
- Схема: `docker exec grodno-db psql -U grodno -d grodno -f db/migrations/0005_clients.sql` —
  повторное применение не должно ничего сломать.
- Фронтенд: `npm run typecheck && npx vitest run` в `frontend/`.
- Живая приёмка (C5): сохранить маршрут в одном профиле браузера, открыть в другом с тем же
  `grodno-client-id`, сверить точки, геометрию и время осмотра; затем `DELETE /clients/me` и
  проверить в БД, что маршруты и предпочтения исчезли.
- Ничего не объявляется сделанным без фактического вывода команды.
