# Spec 003 — сущность клиента: сохранение маршрутов и предпочтений

Статус: в работе. Основание — запрос продукта: «чтобы сохранять маршруты, предпочтения и т.д.».
Сегодня маршруты, время осмотра и прогресс прохода лежат в `localStorage`
(`grodno-route-history`, `grodno-guide-visit-minutes`, `grodno-guide-progress`) — они теряются при
смене браузера, очистке хранилища и не переживают переустановку. Это и есть повод завести клиента.

## 1. Что такое «клиент»

Анонимная запись без логина, пароля и персональных данных:

- идентификатор — UUIDv4, который браузер создаёт один раз и хранит в `localStorage.grodno-client-id`;
- уходит заголовком `X-Client-Id: <uuid>` на каждом запросе к агенту;
- сервер при первом появлении идентификатора заводит строку в `clients`; незнакомый/отсутствующий
  заголовок — не ошибка, а работа без сохранения;
- «выйти» = удалить идентификатор в браузере; данные клиента при этом остаются на сервере (их
  удаление — отдельное действие, см. §5).

Почему так, а не аккаунты: продукт демонстрационный и туристический; аккаунт требует
подтверждения личности, восстановления доступа и защиты ПДн. Анонимный идентификатор даёт всё,
что нужно для «маршруты и предпочтения не теряются», и не создаёт обязательств по ПДн. Если позже
понадобится вход, анонимного клиента можно повысить до аккаунта, не меняя модель данных.

## 2. Схема (миграция `0005_clients.sql`)

```
clients(id uuid pk, created_at timestamptz, last_seen_at timestamptz)

client_preferences(
  client_id uuid pk references clients on delete cascade,
  transport text,                  -- 'pedestrian' | 'bicycle' | 'auto' | null
  time_budget_minutes int,
  party_adults int,                -- null = «не указано», не выдуманное число
  party_children int,
  interests text[],                -- коды категорий канонической таксономии
  language text,                   -- 'ru' | 'en'
  visit_minutes_by_category jsonb, -- {код категории: минуты} — «мой обычный темп»
  updated_at timestamptz
)

saved_routes(
  id uuid pk,
  client_id uuid not null references clients on delete cascade,
  name text,                       -- как назвал сам турист, может быть пустым
  query text not null,             -- исходный запрос: по нему маршрут восстанавливается
  plan jsonb not null,             -- проверенный TripPlan целиком (точки, геометрия, манёвры,
                                   -- requirements, costing, summary) — ровно то, что показали
  visit_overrides jsonb,           -- {id точки: минуты} — время осмотра, если турист его менял
  created_at timestamptz,
  updated_at timestamptz
)
index on saved_routes(client_id, created_at desc)
```

`plan` хранится как есть, а не пересобирается при чтении: восстановленный маршрут обязан совпадать
с тем, что турист видел. Пересборка — отдельное действие пользователя, не побочный эффект чтения.

## 3. Эндпойнты

Все — под `/clients/me`, требуют `X-Client-Id`. Ответы — машинные коды, не русский текст.
Без БД или с недоступным хранилищем — `503`, код `storage_unavailable`: клиент продолжает работать
локально и честно говорит, что сохранение недоступно.

- `GET  /clients/me/preferences` → `200` с сохранёнными полями (отсутствующие — `null`/пусто).
- `PUT  /clients/me/preferences` → частичное обновление: обновляются только переданные поля,
  `null` явно очищает поле. → `200` с новым состоянием.
- `POST /clients/me/routes` `{query, plan, name?, visit_overrides?}` → `201 {id, created_at}`.
- `GET  /clients/me/routes?limit=50` → список без тяжёлой геометрии:
  `{id, name, query, created_at, stop_count, distance_m, duration_min}`.
- `GET  /clients/me/routes/{id}` → полная сохранённая запись (`plan`, `visit_overrides`).
- `PATCH /clients/me/routes/{id}` `{name}` → переименование.
- `DELETE /clients/me/routes/{id}` → `204`.

Коды причин (в ответе, не русским текстом): `storage_unavailable`, `route_not_found`,
`invalid_client_id`, `too_many_routes`.

## 4. Поведение фронтенда

- Идентификатор создаётся при первом обращении и один раз: `crypto.randomUUID()`, ключ
  `grodno-client-id`.
- После успешной сборки маршрут **не** сохраняется молча. Сохранение — действие туриста
  («сохранить маршрут»); молчаливое накопление чужих маршрутов делает список бесполезным.
- Сохранение уходит и на сервер, и (при недоступности) остаётся локально: локальная копия —
  резерв, а не второй источник правды. В списке видно, что сохранено на сервере.
- Предпочтения подтягиваются при запуске и предзаполняют UI (транспорт, бюджет времени,
  состав группы, интересы, язык, «мой обычный темп» по категориям). Изменение — сохраняется
  (с задержкой, без кнопки «сохранить»).
- Время осмотра остаётся выбором внутри маршрута; при сохранении маршрута оно уезжает вместе с
  `visit_overrides` и возвращается при восстановлении.
- Прогресс прохода (`visited`, метры) НЕ уезжает на сервер: это состояние текущей прогулки, а не
  факт о туристе.

## 5. Удаление и приватность

- `DELETE /clients/me` — удаляет клиента со всеми его маршрутами и предпочтениями (cascade).
  Показывается в UI как «удалить мои данные» с честным текстом, что локальные копии удаляются там же.
- Ничего, что позволяет опознать человека, не хранится: ни имён, ни почты, ни координат
  постоянного места жительства. Геолокация используется только на время прогулки и на сервер не
  уходит.

## 6. Что НЕ делаем в этой версии

- Аккаунты, пароли, подтверждение почты, восстановление доступа.
- Синхронизацию между устройствами через ссылку/код (возможный следующий шаг).
- Совместные маршруты и роли.

## 7. Приёмка

- [ ] Миграция применяется на живой БД идемпотентно, без потери существующих данных.
- [ ] Запрос без `X-Client-Id` работает как раньше, сохранение при этом недоступно (честно).
- [ ] Маршрут, сохранённый в одном браузере, открывается в другом по тому же `client_id` и
      совпадает с ним точками, геометрией, временем осмотра.
- [ ] Предпочтения подтягиваются при запуске и меняют предзаполнение UI.
- [ ] `DELETE /clients/me` действительно удаляет маршруты и предпочтения (проверено запросом к БД).
- [ ] Недоступное хранилище → `503 storage_unavailable`, UI работает локально и говорит правду.
- [ ] Тесты бэкенда и фронтенда зелёные; живой прогон с выводом приложен.
