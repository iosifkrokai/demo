# Spec 005 — аккаунты и роли, посещённые места, админка

Статус: в работе. Основание — запрос продукта: «создать юзеров и админов, сохранять
посещённые места, ну и админка».

Развивает spec 003 (анонимный клиент). Там аккаунты были сознательно отложены: «Если позже
понадобится вход, анонимного клиента можно повысить до аккаунта, не меняя модель данных»
(§1). Это и есть та поездка: анонимный `client_id` **не выбрасывается**, а присваивается
аккаунту при регистрации/входе.

## 1. Что меняется в продукте

Сегодня есть анонимный клиент (`X-Client-Id`) с сохранёнными маршрутами и предпочтениями, но
нет ни входа, ни ролей, ни админки, и «посещённые места» живут только в `localStorage`
(`grodno-guide-progress`) как прогресс текущей прогулки.

Добавляем три вещи:

1. **Аккаунты и роли.** `user` / `admin`. Вход по email+паролю, серверная сессия.
2. **Посещённые места.** Персональный реестр: какие места турист отметил посещёнными. Хранится
   на сервере, привязан к аккаунту, переживает смену браузера.
3. **Админка.** Управление пользователями (список, роль, удаление) и местами (поиск,
   создание, правка, удаление) через отдельный раздел UI.

## 2. Модель данных (миграция `0008_accounts_visits.sql`)

```
users(
  id            uuid pk,
  email         citext not null unique,     -- регистр не важен
  password_hash text not null,              -- scrypt, формат ниже
  display_name  text,                       -- как показывать; необязательно
  role          text not null default 'user' check (role in ('user','admin')),
  client_id     uuid unique references clients(id) on delete set null,
                                            -- анонимный клиент, присвоенный аккаунту
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now(),
  last_login_at timestamptz
)

user_sessions(
  token_hash   text pk,                      -- sha256(token); сам токен не хранится
  user_id      uuid not null references users(id) on delete cascade,
  created_at   timestamptz not null default now(),
  expires_at   timestamptz not null,
  last_seen_at timestamptz not null default now()
)
index on user_sessions(user_id)

visited_places(
  user_id    uuid not null references users(id) on delete cascade,
  place_id   integer not null references places(id) on delete cascade,
  visited_at timestamptz not null default now(),
  primary key (user_id, place_id)
)
index on visited_places(user_id, visited_at desc)
```

Требует расширения `citext` (включается в миграции и в `init.sql`).

**Почему scrypt, а не argon2.** Хешируется стандартной библиотекой (`hashlib.scrypt`,
N=2^15, r=8, p=1, соль 16 байт), формат `scrypt$n$r$p$salt_b64$hash_b64`, сравнение
constant-time. Это не тянет новую рантайм-зависимость и не имеет шага сборки; алгоритм
заменяем позже (формат самодокументирован — префикс несёт параметры).

**Прогресс прогулки остаётся локальным.** `guide-panel` по-прежнему ведёт `visited` текущего
прохода в `localStorage`: это состояние прогулки, а не факт о туристе (spec 003 §4). Новый
реестр `visited_places` — это явная отметка «я здесь был», из карточки места или из проводника,
и она durable.

## 3. Эндпойнты

Машинные коды причин вместо русского текста (как в spec 003). Общее:
`storage_unavailable` (503), `not_authenticated` (401), `not_admin` (403),
`invalid_request` (422), `place_not_found` / `user_not_found` (404).

### Аутентификация (публичные)

- `POST /auth/register` `{email, password, display_name?}` → `201 {user}` + сессионная кука.
  Роль всегда `user`. Если отправлен `X-Client-Id` — он присваивается аккаунту (если уже
  занят другим — просто не присваивается, регистрация не падает).
  Коды: `email_taken` (409), `invalid_email` (422), `weak_password` (422).
- `POST /auth/login` `{email, password}` → `200 {user}` + кука. Код: `invalid_credentials` (401).
- `POST /auth/logout` → `204`, сессия удалена, кука очищена.
- `GET  /auth/me` → `200 {authenticated: bool, user: {...}|null}` — без 401, чтобы SPA стартовал тихо.

`user` в ответах: `{id, email, display_name, role, created_at}` — `password_hash` не покидает сервер.

Сессия: кука `grodno_session`, `HttpOnly`, `SameSite=Lax`, `Path=/`, `Max-Age` 30 дней,
`Secure` только по https. Токен — `secrets.token_urlsafe(32)`; в БД — только `sha256`.

### Посещённые места (требуют входа)

- `GET    /me/visited` → `{items: [{place_id, visited_at, name, category, town, district, lat, lon, photo}], count}`
  (данные места подмешиваются из `places`, чтобы список/карта рисовались одним запросом).
- `PUT    /me/visited/{place_id}` → `200 {place_id, visited_at}`; идемпотентно (upsert).
- `DELETE /me/visited/{place_id}` → `204`; идемпотентно.
- `POST   /me/visited` `{place_ids: [int]}` → `{marked: [int], count}` — отметить пачку
  (например, все остановки пройденного маршрута) одним запросом.

### Админка (требуют `role=admin`)

- `GET    /admin/users?q=&limit=&offset=` → `{items: [{id, email, display_name, role,
  client_id, created_at, last_login_at, saved_routes, visited}], total}`
- `PATCH  /admin/users/{id}` `{role?, display_name?}` → `{user}`. Правила: нельзя снять роль
  admin с последнего админа (`last_admin`, 409); нельзя менять свою роль (`self_role`, 409).
- `DELETE /admin/users/{id}` → `204`. Нельзя удалить себя (`self_delete`) и последнего админа.
- `GET    /admin/places?q=&category=&limit=&offset=` → `{items: [...], total}`
- `POST   /admin/places` `{name, lat, lon, source_url, category?, town?, district?, blurb?,
  fun_fact?, visit_minutes?, opening_hours?, ticket_price?}` → `201 {place}`.
- `PATCH  /admin/places/{id}` — частичная правка тех же полей → `{place}`. Правка `category`
  помечает строку `category_source='curated'` и снимает curated-guard для этой транзакции
  (иначе триггер молча вернёт старое значение). Правка `lat`/`lon` двигает точку. Координаты
  **не** принимают `null` (колонки `NOT NULL`, а хендлер пишет каждое присланное поле): пропуск
  ключа = «не менять», явный `null` = `422` — иначе был бы `500` от БД.
- `DELETE /admin/places/{id}` → `204`.
- `GET    /admin/stats` → `{users, admins, places, visited, saved_routes}`.

## 4. Первый админ

Первого администратора заводит скрипт `backend/scripts/create_admin.py --email … --password …`
(идемпотентно: если email занят — повышает до admin, иначе создаёт). В UI админов больше
нельзя «назначить» — только скриптом или другим админом через `PATCH /admin/users/{id}`.

## 5. Поведение фронтенда

- В шапке (поверх карты, справа) — контрол аккаунта: «Войти», а после входа — меню
  («Мои посещённые», «Админка» — если админ, «Выйти»).
- `/login`, `/register` — отдельные страницы-формы, без карты.
- `/visited` — посещённые места **списком и на карте**: та же связка в обе стороны, что в админке
  (клик по строке центрирует карту, клик по пину подсвечивает строку). Карта — общий компонент
  `PlaceMap`, так что точка не может стоять в одном месте на одной странице и в другом на другой.
  В списке — название, категория, город, дата.
- `/admin` — отдельная страница, две вкладки: «Пользователи» и «Места»; правка мест — форма
  по полям, список юзеров с селектором роли и удалением.
- Вкладка «Места» — **две колонки: список и карта, обе видны всегда**. Карта ставит пины
  всех мест текущего списка (страница до 100) и кадрируется по ним; клик по строке (по имени)
  центрирует карту на этой точке, клик по пину на карте подсвечивает и подтягивает строку —
  это два окна на одну страницу, а не список с превью. «изменить» делает пин перетаскиваемым:
  перетаскивание переписывает поля широты/долготы, «сохранить» отправляет их в `PATCH`.
  Карта маленькая и самодостаточная (`PlaceMap`, общий с `/visited`), не приложение-карта:
  у той свои слои, планировщик и сторы, которые в настройках не нужны.
- В карточке места на карте — кнопка-переключатель «Посещено» (виден только вошедшим;
  аноним видит подсказку «войдите, чтобы отмечать»).
- Ошибки — машинные коды, тексты — русские строки UI, как в остальном приложении.

## 5a. Вход обязателен (обновление продукта)

Пользоваться приложением без входа нельзя. Маршруты `/`, `/$activeTab` (карта: направления,
изохроны, тайлы), `/visited`, `/admin` закрыты: `beforeLoad` в `routes.tsx` проверяет сессию
через тот же `authQueryOptions`, что и `useAuth` (одна запись кэша, один источник правды), и
при её отсутствии отправляет на `/login` с `?redirect=<исходный путь>`; после входа форма
возвращает на этот путь (`window.location.assign` — приложение перечитывает сессию с нуля,
чтобы гейт увидел свежую куку, а не старый кэш). Публичны только `/login` и `/register`.

Правило вынесено в чистую функцию `utils/auth-guard.ts` (`loginRedirectFor`) — роутер только
превращает ответ в `redirect()`; сама логика покрыта тестом. Контекст роутера не типизирован
на момент объявления маршрутов, поэтому клиент запроса читается защитно и **fail-closed**:
непроверяемая сессия считается отсутствующей.

**Честная граница.** Гейт стоит в клиенте (роутер). Stateless-эндпойнты планировщика
(`/routes/*`, `/places`, `/clients/*`) сессии **не** требуют — это осознанное решение, а не
недосмотр: они не читают пользовательские данные, а карта и так недостижима без входа.
Данные аккаунта (`/me/*`, `/admin/*`) закрыты сессией на сервере. Закрыть и планировщик —
это добавить зависимость `require_user` на его роутер; шаг сознательно не сделан в этой
версии (сломал бы ~1000 тестов и stateless-природу планировщика).

## 6. Что НЕ делаем в этой версии

- Восстановление пароля, подтверждение email, 2FA, смена пароля (кроме скрипта).
- OAuth/соцвход, шаринг маршрутов, команды/организации.
- Rate limiting и CAPTCHA на вход/регистрацию.
- Мягкое удаление мест; история правок и аудит-лог админки.
- Миграция уже сохранённых локально «посещённых» в аккаунт при первом входе.

## 7. Приёмка

- [ ] Миграция `0008` применяется на живой БД идемпотентно; `init.sql` ей соответствует.
- [ ] Регистрация/вход/выход работают; `GET /auth/me` честно отвечает про состояние.
- [ ] Пароль не покидает сервер ни в одном ответе; в БД лежит только хеш; токена сессии в БД нет.
- [ ] Роль `admin` открывает `/admin/*`, роль `user` получает `403 not_admin`.
- [ ] Посещённое место сохраняется и переживает «перезаход»; повторная отметка идемпотентна.
- [ ] Нельзя остаться без админов (снять роль/удалить последнего) и нельзя удалить себя.
- [ ] Анонимный `X-Client-Id` при регистрации присваивается аккаунту.
- [ ] Тесты бэкенда и фронтенда зелёные; гейты `ruff`/`pyright` чистые.
- [ ] Живой прогон новых эндпойнтов на локальной БД с выводом приложен.
- [ ] Анонимный заход на `/directions`, `/visited`, `/admin` → редирект на `/login`
      с `?redirect=`; после входа возвращает на запрошенный путь. `/login` и `/register`
      открыты без сессии.
